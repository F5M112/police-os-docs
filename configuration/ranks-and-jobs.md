# الرتب والوظائف

يقرأ Police OS وظيفة اللاعب من QBCore: اسم الوظيفة `job.name` ورقم الرتبة `job.grade.level`. كل فحوص الرتب في السكربت هي مقارنة هذا الرقم بأرقام تضعها أنت في `config.lua`، فلا بد أن تناسب أرقامك **سلّم الرتب الفعلي** لوظيفة الشرطة عندك.

## ابدأ بسلّم رتبك

القيم الافتراضية مبنية على سلّم من 0 إلى 18. افتح تعريف وظيفة الشرطة عندك (في qb-core القياسي الملف `qb-core/shared/jobs.lua`، الوظيفة `police`، الجدول `grades`) وانظر أرقام الرتب. المفاتيح هناك هي ما يسميه Police OS «الرتبة». في qb-core القياسي ينتهي السلّم عند رتبة صغيرة (غالبًا 4)، وحينها **لن يصل أحد إلى الرتبة 18 الافتراضية**، ولن تظهر له أي صلاحيات إدارية.

## الأرقام التي تتحكم بها الرتب

| الإعداد | الافتراضي | يتحكم في |
|---|---|---|
| `Config.AdminGrade` | 18 | الأدمن: كل الصلاحيات تلقائيًا في كل التطبيقات، وهو وحده من يستطيع منح `system_admin` و`boss_access` |
| `Config.BossMenu.MinGradeForBoss` | 18 | «البوس»: تطبيق [إدارة الشرطة](../usage/boss.md) (الترقية والفصل والتوظيف وإنشاء الأجنحة وتعيين مسؤوليها) |
| `Config.MinGradeForManager` | 10 | «المدير»: [إدارة الأجنحة](../usage/wings.md) وأعضائها ومسؤوليها، وإعادة فتح التقارير وحذفها |
| `Config.TestSystem.MinGradeToManage` | 10 | «مدير الاختبار»: [إدارة الاختبار](../usage/test-management.md) وقبول النتائج ورفضها وأمر `/createpolicetest` |
| `Config.BossMenu.HireGrade` | 0 | الرتبة التي يوظَّف عليها العسكري الجديد |
| `Config.TestSystem.AcceptedGrade` | 0 | الرتبة التي يُقبل عليها المتدرب بعد `/accepttest` |

{% hint style="info" %}
تغيير أي رقم هنا لا يغيّر أسماء الرتب ولا رواتبها: هذه تبقى في تعريف الوظيفة عندك. والرتب الظاهرة في قائمة الترقية داخل التطبيق تُقرأ من تعريف الوظيفة `Config.PoliceJob` نفسه.
{% endhint %}

## مثال: سلّم قصير (0 إلى 4)

لو كان سلّمك خمس رتب فقط، يكون التوزيع المنطقي مثلًا:

{% code title="config.lua" %}
```lua
Config.AdminGrade         = 4    -- أعلى رتبة
Config.MinGradeForManager = 3    -- الرتبة قبل الأخيرة

Config.BossMenu = {
    MinGradeForBoss = 4,         -- مثل AdminGrade
    HireGrade       = 0,
    -- باقي المفاتيح كما هي
}

Config.TestSystem = {
    MinGradeToManage = 3,
    AcceptedGrade    = 0,
    -- باقي المفاتيح كما هي
}
```
{% endcode %}

هذا مثال توضيحي فقط، فاختر الأرقام التي تناسب هيكل قيادتك.

{% hint style="warning" %}
**الرقم 10 داخل واجهة الـ MDT.** زرّا «إعادة فتح الحالة» و«حذف التقرير» لا يظهران في الواجهة إلا لمن رتبته **10 فما فوق**، وهذا الرقم مكتوب في `html/script.js` وليس في `config.lua`. إن كانت أعلى رتبة عندك أقل من 10 فلن يظهر الزران لأي شخص، حتى لو سمح السيرفر بالعملية (`Config.MinGradeForManager` أو `delete_reports`).

تطبيق إدارة الأجنحة أقل تأثرًا: السيرفر يعيد لمن رتبته `MinGradeForManager` فما فوق (أو يملك `manage_wings`) كل الأجنحة كأجنحة يديرها، فتظهر له رغم الرقم 10.
{% endhint %}

## البوس والأدمن: الفرق

| | الأدمن (`AdminGrade`) | البوس (`MinGradeForBoss`) |
|---|---|---|
| الصلاحيات | **كل المفاتيح** تلقائيًا، حتى لو كان حسابه بلا صلاحيات | حسب ما في حسابه، إضافة إلى عمليات تطبيق الإدارة |
| تطبيق إدارة الحسابات | يعمل (يملك `system_admin`) | يظهر له، لكن عملياته ترفض ما لم يملك `system_admin` |
| منح `system_admin` و`boss_access` | يستطيع | لا يستطيع (تُحذف من الحساب عند الحفظ) |

{% hint style="warning" %}
إن جعلت `MinGradeForBoss` أقل من `AdminGrade` فسيرى هؤلاء البوسات تطبيق «إدارة الحسابات» فارغًا. اترك القيمتين متساويتين، أو امنح `system_admin` لمن تريد.
{% endhint %}

## الوظائف الإضافية

قد تريد أن يحصل ضباط من وظيفة أخرى (قيادة خاصة، أو وحدة بوظيفتها) على النظام نفسه. أضف الوظيفة إلى:

{% code title="config.lua" %}
```lua
Config.ExtraJobNames = { ['hkm'] = true }   -- بحسب job.name
Config.ExtraJobTypes = { ['hkm'] = true }   -- بحسب job.type
Config.ExtraJobsBypassGrade = true
```
{% endcode %}

* من يحمل وظيفة إضافية يُعامل كشرطي في كل مكان: يفتح التابلت ويسجل الدخول، وتُحتسب ساعاته إن كان «في الخدمة»، ويظهر في قوائم الضباط والأجنحة.
* **`ExtraJobsBypassGrade = true`**: هذه الوظائف تجتاز كل فحص رتبة **أقل من `AdminGrade`**، أي تعتبر كأنها بلغت `MinGradeForManager` و`MinGradeToManage`. لكنها لا تُعدّ أدمن (الأدمن يتطلب رتبة فعلية)، فلا تحصل على صلاحيات الأدمن التلقائية.
* إن كانت `MinGradeForBoss` أقل من `AdminGrade` فإن هذه الوظائف **تُعدّ بوسًا أيضًا**. حافظ على تساوي القيمتين إن لم تقصد ذلك.
* **`ExtraJobsBypassGrade = false`**: تُقارن رتبتهم الفعلية برقم الفحص كغيرهم.
* لا تريد وظائف إضافية؟ اجعل الجدولين فارغين: `Config.ExtraJobNames = {}` و`Config.ExtraJobTypes = {}`.

{% hint style="info" %}
تغيير الرتبة من تطبيق الإدارة يضع الضابط دائمًا على وظيفة `Config.PoliceJob`، حتى لو كان على وظيفة إضافية.
{% endhint %}

## وظيفة الشرطة نفسها

* `Config.PoliceJob` (الافتراضي `'police'`) هو اسم الوظيفة الرئيسية. إن كانت وظيفتك باسم آخر (مثل `lspd`) فغيّره، ويجب أن تكون معرّفة في وظائف QBCore.
* كل التوظيف والترقية وقبول المتدربين ينتهي بتعيين هذه الوظيفة.
* الفصل يجعل الوظيفة `unemployed` برتبة 0 (اسم الوظيفة هذا ثابت في الكود).
* حالة «في الخدمة» تأتي من `job.onduty` في QBCore، وعلى أساسها تُحسب [الساعات](../usage/hours.md).
