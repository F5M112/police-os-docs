# ديسكورد والويبهوك

يرسل Police OS رسائل منسّقة (Embeds) إلى قنوات ديسكورد عند أحداث محددة: نتائج الاختبارات، وقبول المتدربين ورفضهم، وتقارير الـ MDT، والأحداث الأمنية. كل ذلك اختياري: أي ويبهوك تتركه فارغًا يتوقف إرسال رسائله بصمت دون أخطاء.

## 1) أنشئ الويبهوكات في ديسكورد

لكل قناة تريد استقبال الرسائل فيها:

1. افتح إعدادات سيرفر ديسكورد، ثم **Integrations**، ثم **Webhooks**.
2. اضغط **New Webhook** واختر القناة.
3. اضغط **Copy Webhook URL**.

يمكنك استعمال رابط واحد لعدة أنواع، لكن يُنصح بقناة مستقلة لكل نوع، وقناة **خاصة بالإدارة** للويبهوك الأمني.

## 2) ضعها في server.cfg

{% code title="server.cfg" %}
```ini
set police_wh_results   "https://discord.com/api/webhooks/..."
set police_wh_accepted  "https://discord.com/api/webhooks/..."
set police_wh_rejected  "https://discord.com/api/webhooks/..."
set police_wh_mdt       "https://discord.com/api/webhooks/..."
set police_wh_security  "https://discord.com/api/webhooks/..."

ensure police-os
```
{% endcode %}

{% hint style="danger" %}
استعمل **`set`** وليس `setr`. الأمر `setr` ينسخ المتغير إلى جهاز كل لاعب فيرى الجميع الرابط، ويستطيع أي شخص إرسال رسائل إلى قناتك. وهذا يشمل أيضًا `police_api_token`. لذلك لا تضع الأسرار في `config.lua` أبدًا (هو ملف مشترك مع اللاعبين).
{% endhint %}

* ضع الأسطر **قبل** `ensure police-os`: يقرأ المورد القيم مرة واحدة عند تحميله. وبعد تعديلها نفّذ `restart police-os`.
* ويبهوك غير مضبوط أو فارغ = ذلك النوع من الرسائل معطّل.
* ابقِ `server.cfg` خاصًا. وإن تسرّب رابط ويبهوك فاحذفه من إعدادات القناة في ديسكورد وأنشئ غيره.

## ماذا يرسل كل ويبهوك؟

| المتغير | الرسالة | متى تُرسل |
|---|---|---|
| `police_wh_results` | **📋 نتيجة اختبار الشرطة**: رقم النتيجة، المتدرب، المعرّف، ديسكورد (منشن للمتدرب)، المدرب، النتيجة (صحيح/الكل ونسبتها) و«ناجح ✅» أو «راسب ❌» | عند «إرسال الاختبار» من [اختبار الشرطة](../usage/police-test.md) |
| `police_wh_accepted` | **✅ تم قبول متدرب**: المتدرب، المعرّف، رقم النتيجة | عند تنفيذ `/accepttest` |
| `police_wh_rejected` | **❌ تم رفض متدرب**: المتدرب، المعرّف، رقم النتيجة | عند تنفيذ `/rejecttest` |
| `police_wh_mdt` | **📝 تقرير جديد — نوع التقرير**: رقم التقرير، العنوان، خزنة الأدلة، المشتبه بهم، العساكر المشاركون، التهم، الضابط المحرر | عند حفظ تقرير في [MDT](../usage/mdt.md) |
| `police_wh_security` | **⚠️ محاولة دخول فاشلة**: الرقم الوظيفي، السبب، رقم اللاعب في السيرفر. و**🎖️ حساب جديد تم إنشاؤه (API)**: اسم الضابط، رقم وظيفي، الإداري | عند فشل تسجيل دخول إلى التابلت، وعند إنشاء حساب عبر [HTTP API](../admin/http-api.md) |

* أسباب فشل الدخول التي تظهر في الويبهوك الأمني: «رقم وظيفي غير موجود»، و«كلمة مرور خاطئة»، و«حساب معطل»، و«تجاوز عدد المحاولات». الفرق بين «رقم وظيفي غير موجود» و«كلمة مرور خاطئة» يصل للإدارة فقط، أما اللاعب فيرى في الحالتين الرسالة نفسها.
* الحسابات التي تُنشأ من تطبيق [إدارة الحسابات](../usage/accounts.md) أو بأوامر الكونسول **لا ترسل** رسالة إلى الويبهوك الأمني، فقط الحسابات المنشأة عبر الـ API.
* الرسائل تُكتب بلغة الإدارة `Config.Locale` وليس بلغة اللاعب.

## ألوان الرسائل

* ألوان رسائل النتيجة والقبول والرفض تضبطها من `Config.TestSystem.Colors`، انظر [مرجع config.lua](config-reference.md).
* لون رسالة تقرير الـ MDT ورسالة فشل الدخول أحمر (`#E74C3C`)، ولون رسالة الحساب الجديد عبر الـ API أخضر (`#1EFA05`)، وكلاهما ثابت في الكود.

## معرّف ديسكورد (Discord ID)

يطلبه النظام في موضعين: حساب الضابط، ونموذج [اختبار الشرطة](../usage/police-test.md). وهو رقم من **17 إلى 19 خانة**. للحصول عليه من حساب ديسكورد:

1. فعّل **Developer Mode** من إعدادات ديسكورد (قسم Advanced).
2. اضغط بزر الفأرة الأيمن على المستخدم واختر **Copy User ID**.

## استكشاف الأخطاء

* **لا تصل رسائل:** تأكد أن الرابط صحيح ولم يُحذف الويبهوك، وأنه موضوع بـ `set` قبل `ensure`، وأنك أعدت تشغيل المورد بعد التعديل، وأن السيرفر يستطيع الاتصال بـ discord.com.
* **لا تظهر أخطاء عند الفشل:** الإرسال يتم في الخلفية دون معالجة أخطاء، فلا ينبئك السيرفر بفشل رسالة. جرّب بحدث بسيط مثل إرسال نتيجة اختبار تجريبية.
* **اختبر الأمان:** سجّل دخولًا بكلمة مرور خاطئة عمدًا وتأكد من وصول الرسالة إلى القناة الخاصة.
