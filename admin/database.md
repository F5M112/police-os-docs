# قاعدة البيانات

يستعمل Police OS قاعدة بيانات MySQL أو MariaDB عبر **oxmysql**. **لا يوجد ملف SQL للاستيراد**: ينشئ المورد جداوله بنفسه.

## الإنشاء والترقية التلقائيان

* عند تشغيل المورد، وبعد أن يصبح `oxmysql` جاهزًا، يُنشئ كل جدول ناقص بالأمر `CREATE TABLE IF NOT EXISTS`.
* إن كان جدول موجودًا من إصدار أقدم تُضاف إليه الأعمدة الناقصة تلقائيًا دون حذف بيانات، وتظهر في الكونسول رسالة «أُضيف العمود جدول.عمود».
* عند الانتهاء تظهر في كونسول السيرفر الرسالة «قاعدة البيانات جاهزة».
* لذلك يجب أن يملك مستخدم قاعدة البيانات في إعداد oxmysql صلاحيتي `CREATE` و`ALTER`.

{% hint style="info" %}
رسائل الكونسول تظهر بلغة الإدارة `Config.Locale`. إن لم تظهر «قاعدة البيانات جاهزة» (أو ما يقابلها) فراجع الكونسول بحثًا عن خطأ من oxmysql، وتأكد أنه يعمل ومتصل بقاعدة البيانات.
{% endhint %}

## الجداول التي ينشئها المورد (12)

| الجدول | ما يخزّنه |
|---|---|
| `police_officer_accounts` | حسابات الدخول: الرقم الوظيفي (فريد)، وكلمة المرور المجزّأة، ومعرّف ديسكورد، والاسم، والحالة `is_active`، والصلاحيات JSON، و`created_by`، و`last_login` |
| `police_login_logs` | سجل الدخول: الرقم الوظيفي، ومعرّف ديسكورد، والحالة (`success` أو `failed`)، وعنوان IP، والوقت |
| `police_wings` | عضوية الأجنحة (مواطن + جناح، فريدان معًا) |
| `police_wing_managers` | مسؤولو الأجنحة |
| `police_custom_wings` | الأجنحة التي ينشئها البوس: المعرّف، والاسم، والأيقونة، والمركبات، ونقطة الإخراج |
| `police_hours` | مجموع دقائق كل ضابط في `total_minutes` |
| `police_test_questions` | أسئلة اختبار القبول |
| `police_test_trainers` | المدربون المعتمدون |
| `police_test_results` | نتائج الاختبار وحالتها: `pending` أو `accepted` أو `rejected` |
| `mdt_reports` | تقارير الحوادث: العنوان، والمشتبه بهم، والعساكر، والتهم، والسرد، والحالة، والغرامة والسجن (الأساسي والنهائي) |
| `mdt_vehicle_flags` | إشارات المركبات: اللوحة، ونوع الإشارة، والسبب، واسم الضابط |
| `mdt_case_types` | أنواع القضايا: الاسم والغرامة ومدة السجن |

## جداول خارجية يتعامل معها

لا ينشئها المورد، وهي من جداول QBCore وإضافاتك:

| الجدول | الاستعمال |
|---|---|
| `players` | قراءة اسم المواطن (`charinfo`) ووظيفته (`job`) وبياناته (`metadata`). وتعديل الوظيفة مباشرة بـ `JSON_SET` لمن **غير المتصل** عند توظيفه أو فصله أو تغيير رتبته أو قبوله في الاختبار |
| `player_vehicles` | مركبات المواطن في ملفه وبحث اللوحات في MDT |
| `next_housing` | **اختياري**: منازل المواطن. إن لم يوجد يبقى قسم المنازل فارغًا دون أخطاء |

{% hint style="warning" %}
تعديل وظيفة اللاعب غير المتصل يعتمد على دوال JSON في قاعدة البيانات (MySQL 5.7+ أو MariaDB 10.2+) وعلى أن عمود `job` في `players` بصيغة JSON كما في QBCore القياسي.
{% endhint %}

## الصيانة

### النسخ الاحتياطي

أدرج الجداول الاثني عشر في نسخك الاحتياطي المعتاد. فقدان `police_officer_accounts` يعني فقدان حسابات الضباط وصلاحياتهم.

### تنظيف سجل الدخول

يُكتب في `police_login_logs` سطر مع كل محاولة دخول، **دون أي تنظيف تلقائي**، فينمو الجدول مع الوقت. تنظيف دوري اختياري:

```sql
DELETE FROM police_login_logs WHERE login_time < NOW() - INTERVAL 90 DAY;
```

### حذف نهائي

حذف تقرير من MDT أو سؤال من الاختبار أو نوع قضية يحذفه من الجدول نهائيًا، ولا توجد سلة محذوفات. اعتمد على النسخ الاحتياطي.

## استعلامات مفيدة

آخر محاولات الدخول الفاشلة:

```sql
SELECT badge_number, ip_address, login_time
FROM police_login_logs WHERE status = 'failed'
ORDER BY login_time DESC LIMIT 50;
```

أعلى الضباط ساعات:

```sql
SELECT citizenid, ROUND(total_minutes / 60, 1) AS hours
FROM police_hours ORDER BY total_minutes DESC LIMIT 20;
```

نتائج الاختبار المعلّقة:

```sql
SELECT id, trainee_name, score_pct, created_at
FROM police_test_results WHERE status = 'pending';
```

{% hint style="danger" %}
تجنّب تعديل العمودين `permissions` و`password` يدويًا في قاعدة البيانات. الصلاحيات تُعدَّل بالأوامر أو من التطبيق (فهي JSON لا تقبل غير صيغة صحيحة)، وكلمات المرور تُخزَّن مجزّأة، فاستعمل `chpassword` أو تطبيق إدارة الحسابات لتغييرها.
{% endhint %}
